# 9. External Interfaces

## gov-mine CLI (CLI)

- Audience: the developer; anyone reproducing the runs.
- Purpose and main tasks: seed, create and control runs, inspect, report, export, replay.
- Structure:
  - `gov-mine seed` (the CreateTO institution)
  - `gov-mine run create <institution> [--full|--incremental] [--limit N]`, `run status <id>`,
    `run cancel <id>`, `run report <id> [<id>]`
  - `gov-mine worker [--concurrency N]`
  - `gov-mine pages list|show <id>`; `gov-mine documents list [--type] [--since]`
  - `gov-mine records list --type project`, `records show <id>`, `records history <id>`
  - `gov-mine extract --dry-run --source <id> --extractor rule:createto_project@1`
  - `gov-mine extract --rerun --extractor model:project@2 [--institution <id>] [--type
    project]`
  - `gov-mine review list`, `review approve|reject <id> [--note]`
  - `gov-mine export --since 2021-10-26 --out out/`
  - `gov-mine dev replay --from fixtures/` (serves saved copies for the variants)
- Key inputs and outputs: ids and names in; tables on the terminal; JSON with `--json`.
- Conventions: Typer; `--help` on every command; exit code non-zero on failure; nothing
  interactive.

## Dashboard (GUI)

- Audience: the operator.
- Purpose and main tasks: add any institution and crawl it; watch a run; browse what was
  fetched, kept, extracted and cited; read the report; pause an institution; edit a host's
  policy.
- Structure (screens and navigation):
  - Institutions: list with type, website, last run, next scheduled run, paused toggle. Add and
    edit forms. An institution page with its sources (type, interval, next crawl, extractor),
    documents by type, records by type, and runs.
  - Runs: list with institution, trigger, status, elapsed, live counts and cost. A run page
    with the report; tabs for fetches (filter by outcome, search by URL), snapshots written,
    documents found or changed, records created or amended, AI calls by purpose.
  - Pages: a webpage with its fetch history and snapshots; a snapshot with its markdown per
    page and the raw file download.
  - Documents: list by institution, type and date; a document page with its versions and the
    records extracted from it.
  - Records: list by type with the typed columns; a record page with every field, its citation
    (link to the snapshot page with the excerpt highlighted, verified flag) and the history of
    record snapshots as a diff.
  - Review: the queue of classifications and extractions below the thresholds; an item page
    with the page or the fields and citations, Approve and Reject buttons and a note.
  - Domains: hosts with policy, delay and robots status; edit policy.
  - Settings: extractor and parser versions, models, price list version, cost ceiling, review
    thresholds.
- Key inputs and outputs: forms for institution, domain policy, run creation and review
  decisions; everything else is read.
- Conventions: Alloy's app shell without its workspace route segment (Next.js 16, shadcn/ui,
  TanStack Query and Table);
  every list is a server-paginated table with filters in the URL; live pages poll every few
  seconds; no number is computed in the browser.

## HTTP API (API)

- Audience: the dashboard; the CLI's JSON mode; a downstream service.
- Purpose: everything the dashboard shows and does.
- Structure: `GET|POST /institutions`, `PATCH /institutions/{id}` (pause), `GET|PATCH
  /domains`, `GET|POST /runs`, `POST /runs/{id}/cancel`, `GET /runs/{id}/report`, `GET
  /runs/{id}/fetches`, `GET /webpages/{id}`, `GET /snapshots/{id}/text/{page}`, `GET
  /snapshots/{id}/bytes`, `GET /documents`, `GET /documents/{id}`, `GET /records?type=`, `GET
  /records/{id}` (fields, citations, history), `GET /ai-calls?run=`, `GET /review`, `POST
  /review-decisions`, `GET /settings`. OpenAPI generated by FastAPI; the dashboard's client is
  generated from it.
- Conventions: JSON; UUIDs; cursor pagination; no versioning prefix in phase 1; the API binds
  to localhost, or to Railway's private network when hosted (section 13).

## Export files (files)

- Audience: another service.
- Structure: `out/projects.jsonl`, `news_items.jsonl`, `meetings.jsonl`, `contacts.jsonl`,
  `rfps.jsonl`, `grants.jsonl`, `contracts.jsonl`, `documents.jsonl`, `citations.jsonl`,
  `manifest.json`.
- Key fields: each record line carries `id`, `institution`, `document` (its URL), `key`, the
  typed fields, `citations: [{field, url, page, excerpt, verified}]`, `first_seen_at`,
  `last_changed_at`.

## Crawler identity (other)

- The user agent is `my-bot/<version>`. robots.txt is honoured for `*` and
  for `my-bot`.
