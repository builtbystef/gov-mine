# apps/server

The FastAPI app and the Procrastinate worker (Python package `gov_mine`, distribution `gov-mine-server`).

```sh
vp run dev:api       # from the repo root, http://127.0.0.1:8000/docs
vp run dev:worker    # the job worker, restarted on changes
```

```text
apps/server/
├── src/gov_mine/
│   ├── asgi.py           # entry point for `fastapi run`/`fastapi dev`
│   ├── main.py           # create_app(settings): the API and its lifespan
│   ├── cli.py            # `gov-mine`, the command line
│   ├── config.py         # Settings; every GOV_MINE_* variable is documented in .env.example
│   ├── resources.py      # what every process opens once: database, store, queue, HTTP client
│   ├── modules/          # one package per feature: health, institutions, crawl, ingest, classify, runs, ledger (the rest per docs/specification/06-architecture.md)
│   │   └── <feature>/    # router.py, schemas.py, models.py, service.py, jobs.py
│   ├── integrations/     # ports with their adapters: storage, ai, http (the crawler's client), parser (bytes to markdown pages)
│   ├── jobs/             # the worker, the task registry, and platform tasks (stalled)
│   ├── db/               # declarative base, checked strings, session, and models.py, which imports every model
│   └── shared/           # AppError and subclasses, middleware, logs, telemetry, URL normalising, link finding, sitemap and robots.txt reading, private addresses
├── alembic/              # migrations
└── tests/
    ├── unit/
    └── integration/      # real PostgreSQL, one rolled-back transaction per test
```

## Rules the code relies on

- **One place for the work.** A module's `service.py` does the work and raises `AppError`s. Routes, the CLI, and the worker's jobs all call the same service functions; none holds logic of its own.
- **No repository layer.** Services take the session; the session is the unit of work.
- **Narrow imports between modules.** A module imports another only through its `service`, `models`, `schemas`, and `dependencies`. Helpers with no feature of their own go in `shared/`.
- **The environment is read at the entry points.** Only `asgi.py` and `cli.py` read it. Everything else, tests included, receives a `Settings`.
- **Jobs commit with their data.** A job is queued on the handler's session, so it commits or rolls back with the rows it is about.
- **Tests never call a model.** The test settings drop the OpenRouter key; a test that needs a model answers OpenRouter itself through an `httpx2` mock transport.

## Adding things

- **A model**: import its module in `db/models.py` so Alembic sees it, then add a migration: `uv run alembic revision --autogenerate -m "..."` from `apps/server`. CI fails on a model without a migration. An enumeration is a checked string (`db/checked_strings.py`): autogenerate writes it as a `CheckedString()` column without its constraint, so write it with a `checked()` helper as `alembic/versions/2026_10_27_0811-eb3ad4f1d8e7_crawl_the_homepage.py` does.
- **A route, or a change to request or response shapes**: run `vp run generate` from the root to regenerate the typed client.
- **A job**: put it in a `jobs.py` next to what it works on, register it with `task()`, and list the module in `TASK_MODULES` in `jobs/__init__.py`.
- **A setting**: add it to `Settings` and document it in `.env.example`.
- **A Procrastinate upgrade**: if the new version ships SQL migrations (`procrastinate/sql/migrations/` in the package), add an Alembic migration that runs them. `alembic/env.py` leaves the `procrastinate_*` tables out of autogenerate.

## How it works

- **Errors and logs**: every response and log line carries `X-Request-ID`. A line written inside a job also carries `job_id`, and the `run_id` and `webpage_id` the job was queued with (`LOGGED_ARGUMENTS` in `jobs/tasks.py`), as JSON fields with `GOV_MINE_LOG_FORMAT=json`. Unhandled exceptions become a plain 500.
- **Database**: SQLAlchemy 2 async over psycopg 3, migrations with Alembic.
- **Storage**: S3-compatible (RustFS locally); downloads use presigned URLs.
- **Jobs**: [Procrastinate](https://procrastinate.readthedocs.io) on the app's PostgreSQL, with no broker.
- **Runs**: `gov-mine run create` queues `crawl.start`, which reads the host's `/sitemap.xml` (and the sitemap files an index points to on that host), queues a fetch at depth 0 for the homepage and every URL listed, and queues `crawl.finish`. Reading the sitemap writes no `fetches` row and does not count toward `--limit`. A fetched HTML page queues a fetch one link deeper for every URL in it (`<a href>` and any absolute URL in the raw HTML) that the run has not queued yet; the fence in `crawl.fetch` first refuses any URL whose host is, or resolves to, an address that is not public (private, loopback, link-local and the like; `shared/addresses.py`) as `skipped_scope` `private_address`, whatever its host's policy, then refuses what is outside the institution's website prefix or more than 50 links deep with a `fetches` row and no request. Other hosts go by their domain's `crawl_policy`: a host seen for the first time is `files_only`, where only URLs with a file extension (`FILE_EXTENSIONS` in `shared/urls.py`) are fetched and nothing they hold is followed; a `blocked` host is never fetched; a `crawl` host other than the institution's is in scope whole. Until platform rules exist, a `platform` host is refused too. A URL that passes the fence is then checked against its host's robots.txt, read by the first such URL on the host in the run into `domains.robots_txt` (under the domain row's lock, so once per run) and honoured for `*` and for `my-bot`, the crawler's name (`ROBOT_NAME` in `integrations/http`; every request sends `User-Agent: my-bot/<version>`): what it disallows is `blocked_robots` with no request. Last, a URL whose extension names a type the crawler never downloads (`UNSUPPORTED_EXTENSIONS` in `shared/urls.py`: archives, programs, video and audio, images, scripts, styles, fonts, data) is `skipped_type` with no request. A page or file costs one GET and no HEAD: its body is streamed, and a 200 whose `Content-Type` is not HTML, PDF, an office file, csv or plain text (`SUPPORTED_MEDIA_TYPES`; images are not downloaded until OCR exists; not asked when the URL's extension is in `FILE_EXTENSIONS`) is `skipped_type`, and one whose `Content-Length` is over the run's `settings.max_file_bytes` (100 MB, read as 100 × 1024 × 1024 bytes: `MAX_FILE_BYTES`) is `skipped_size`, both before the body is read; a body that streams past the cap is dropped as `skipped_size` and writes no snapshot. A timeout, a 429 or a 5xx is tried again up to three times in the same job (`RETRIES`), 1 s, 2 s and 4 s later (on top of the host's delay), each try its own `fetches` row that counts toward `--limit`; any other non-200 is one `failed_http` row. A 404 sets `webpages.missing_since`, and a later 200 clears it. A 4xx robots.txt allows everything; a 5xx or failed one refuses the host's URLs (`robots_unreachable`) until the next run. `crawl_delay_ms` is its `Crawl-delay` or 1 s, whichever is longer. Reading robots.txt writes no `fetches` row and does not count toward `--limit`. A host is sent one request at a time, `crawl_delay_ms` apart: fetch jobs carry a Procrastinate `lock` keyed by their domain id, so a host's fetches run one after another in the order queued, whatever the worker's concurrency, and every request to a host (sitemap and robots.txt included) first waits until `crawl_delay_ms` has passed since `domains.last_request_at`, then sets it, holding the domain row's lock until its transaction ends; a sent request's `fetches.requested_at` is when it was sent. The worker polls for jobs every 0.1 s, since Procrastinate does not wake it when a lock is released. `--limit N` caps the requests a run sends; the run's advisory lock makes the count and the queueing safe across concurrent fetches. Every job of a run carries `run_id`; `crawl.finish` marks the run finished once no other job with that `run_id` is waiting or running in `procrastinate_jobs`, and looks again every few seconds until then. A full run whose homepage's last try failed ends `failed` instead, with why in `crawl_runs.error`; a failure on any other page does not fail the run.
- **Parsing**: `ingest.store` queues `ingest.parse(run_id, snapshot_id)` with every new snapshot, in the same transaction. It runs the parser port (`integrations/parser`, pure, run in a thread) for the snapshot's media type and writes one markdown object per page at `text/<snapshot id>/<page>`, pages from 1, then sets `parser` and moves `text_status` from `parsing` to `ready`. HTML (`html:compact@1`) is one page: selectolax removes scripts, styles, SVG, forms, `nav`, `footer`, the page's `header` (one outside `main` and `article`) and ARIA navigation, banner and footer roles, then markdownify converts the rest. A PDF (`pdf:markitdown@1`) is split into one-page PDFs with pypdfium2 and each read by MarkItDown, so page N of the PDF is `text/<id>/N`; a pptx is a page per slide, an xlsx or xls a page per sheet, a docx one page (`<ext>:markitdown@1`); csv and plain text are one page as they are (`text:plain@1`). An image is `none`, with no text objects. Bytes no parser reads (a corrupt file, or a type with no parser such as a legacy .doc) leave the snapshot `failed` with the error in `text_error`; the job succeeds, so it is not retried, and the bytes and the fetch are untouched. `ingest.text` reads a page back, raising `TextNotReady` (409) while `parsing` and `NoText` (404) for `none` or `failed`; `GET /snapshots/{id}/text/{page}` serves it as `text/markdown`, and `GET /snapshots/{id}/bytes` serves the stored bytes with the snapshot's media type.
- **Classifying**: after parsing, `ingest.parse` queues `classify.page(run_id, snapshot_id)` when the snapshot has text, an OpenRouter key is configured, and the webpage has no classification and is not a document; a page is classified once, on its first snapshot with text. `classify.page` sends Jev (`integrations/ai/jev.py`, a thin httpx client over `POST /api/alpha/decisions`, `Resources.models_http`) one `page_type` choice question with 25 criteria (`none`, and `listing:<type>` and `document:<type>` for every `DocumentType` but `project_material`) and a `state` of URL, title (an HTML page's `<title>`, else the file name), at most 100 links within 6,000 bytes, and the markdown from the top cut at a paragraph boundary, the whole body under 32,000 bytes (`build_request`). A provider error is tried once more, then stored in `classifications.error` with no `ai_calls` row. An answer writes one `classifications` row (`jev:classify@1`, unique per snapshot and classifier; `confidence` is the choice's probability, `raw_output` the whole answer) and one `ai_calls` row linked to it. `listing:<type>` upserts a `sources` row of the run's institution (`crawl_interval` 1 day for press releases, 7 for projects and RFPs, 30 otherwise; `next_crawl_at` from the snapshot's first fetch); `document:<type>` upserts a `documents` row with the title and the snapshot's `stated_date`, under the source whose webpage linked to it, if any. `GET /ai-calls?run=`, `GET /runs/{id}/sources` and `GET /runs/{id}/document-counts` read them back.
- **Models**: every model goes through OpenRouter, turned on by `GOV_MINE_OPENROUTER_API_KEY` (`integrations/ai`): the extraction and OCR model through [Pydantic AI](https://pydantic.dev/docs/ai/) (`create_model`, `extract_model_settings`); Jev calls the Decisions API directly and builds its `Usage` from the response. Every paid call is one `ai_calls` row, written by `ledger.service.record` from a `Usage` (`usages(messages)` reads them from an agent run): `cost` is computed from the versioned price list in `modules/ledger/prices.py`, and `reported_cost` keeps what OpenRouter said it charged. A model not in the list raises `UnpricedModelError`; check `price_of(model)` before calling one.
